# 赛后喊话上下文预实验（2026-10-24）

## 目的

比较两种赛后喊话上下文：

- `full`：把赛后提示追加到整场 `messages`，保留完整历史。
- `fresh`：用短 system prompt + 整场摘要 + 最后一手结果，不发送比赛历史。

重点看输入 token、缓存、费用和消息质量，不追求统计显著性。

## 设置

- 历史来源：`tmp/context_preview/20261024_042736_full_seed2028/messages.json`
- 20 手连续对局，seed 2028，`full` 策略，最终筹码 1900 对 1100，净 +900。
- 模型：`deepseek/deepseek-flash`，`reasoning_effort=low`
- 每种模式重复 5 次，同一终局、同一模型参数。
- `full` 使用原对局的 `user_id`，模拟真实场景中历史缓存还热着。
- `fresh` 使用新的 `user_id`，第一次调用冷缓存。
- 输出：`tmp/final_talk_preview/`

## 结果

第二次运行（`full` 缓存已热）：

| 模式 | 成功 | 输入 token | 首请求命中 | 稳态命中 | 输出 token | 平均费用 | 上下文消息数 | 历史估算 token | 平均字数 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `full` | 5/5 | 108,500 | 99.8% | 99.8% | 145 | $0.000444 | 243 | 87,372 | 64 |
| `fresh` | 5/5 | 615 | 0.0% | 62.4% | 74 | $0.000092 | 2 | 1,195 | 52 |

第一次运行里 `full` 的第一条请求是冷缓存：

| 模式 | 输入 token | 缓存命中 | 费用 |
|---|---:|---:|---:|
| `full` 冷启动 | 108,500 | 1.1% | $0.016172 |
| `full` 热缓存 | 108,500 | 99.8% | $0.000418 |
| `fresh` 冷启动 | 608 | 0.0% | $0.000145 |
| `fresh` 热缓存 | 608 | 63.2% | $0.000083 |

## 观察

1. **输入量差距很大。** `fresh` 每次 615 token，`full` 每次 108,500 token，约 176 倍。上下文消息数从 243 条降到 2 条。
2. **缓存热的时候，费用差约 5 倍。** `full` 稳态命中 99.8%，费用约 $0.00044；`fresh` 约 $0.00009。`full` 的历史缓存确实很便宜，但仍然比 `fresh` 贵。
3. **缓存冷的时候，费用差约 100 倍。** `full` 冷启动 $0.0162，`fresh` 冷启动 $0.000145。比赛刚结束时历史通常是热的，所以 5 倍是更现实的数字；换进程、缓存过期或换 `user_id` 时会接近 100 倍。
4. **消息质量都能接受。** 两边 5 次都成功调用 `send_table_message`。`full` 会引用具体动作和牌面，变化更多；`fresh` 围绕“20 手、赢 3 手、净赚 900”展开，5 条里没有明显事实错误，但更模板化。
5. **`fresh` 不再有工具不匹配的问题。** `full` 沿用的 system prompt 仍然写着 apply_action 等规则，但赛后只暴露 `send_table_message`。这次没有失败，但这是一个潜在风险；`fresh` 的 system prompt 只讲喊话。
6. **摘要要写清楚“整场结果”。** 第一版摘要没有“盈利/亏损”标签，模型有一次把“赢 3 手、输 17 手、净 +900”表述得比较绕。改成 `【整场结果】...（盈利）` 后，5 条消息都正确区分了整场结果和最后一手。

## 示例消息

`full`：

> 这局打得挺过瘾，你那些小注和 limp-raise 的套路一度让我很头疼，中间连续弃牌都快被你牵着走了。不过关键的两手大池我没松手，最后筹码还是站在我这边。

`fresh`：

> 20手你赢了17手，最后筹码却少了900——赢小输大，这就是德州。牌品不错，下次记得别把大底池都让给我。

## 注意

- 只有一场对局、每种模式 5 次，质量判断是主观的。
- `full` 的具体性更好，但费用高；`fresh` 更稳定、便宜，但消息更模板化。
- 如果希望 `fresh` 保留更多细节，可以在摘要里加最近 2 到 3 手的关键动作，token 仍然远低于完整历史。
- 生产环境里 `full` 的缓存通常比实验更热，所以不要只看冷启动的 100 倍差距。

## 复现

```bash
python scripts/preview_context.py --policy full --hands 20 --seed 2028 --stream-usage --cache-scope ctx-c-full-20-20261024
python scripts/preview_final_talk.py --history tmp/context_preview/20261024_042736_full_seed2028/messages.json --mode both --repeats 5 --full-cache-scope ctx-c-full-20-20261024 --fresh-cache-scope ctx-c-fresh2-20-20261024
```
